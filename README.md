# ADDHARD サイト管理

NEWS・Q&A・ShapeKeys・EYE Textures・Toolsを追加、編集、削除、上下ボタンで並べ替えできます。TEAMはメンバーごとの制作実績を編集できます。新しく追加したNEWS・商品は先頭に入ります。下書きを保存しても公開サイトは変わりません。「更新して公開」でGitHubへ送信し、Cloudflare Pagesがビルドして反映します。送信成功は公開完了とは区別して表示します。

## 管理画面での編集

- 商品はカテゴリのタブを開き、「＋ 追加」から登録します。商品名、ラベル、説明、商品リンク、画像と代替テキスト、表示・非表示、並び順を編集できます。既存のShapeKeys 9件・EYE Textures 35件・Tools 4件も編集できます。
- 画像はURLを指定するか、PCからPNG・JPEG・WebPを選択します。PCの画像はブラウザーで長辺1600px以下・750KB以下のWebPへ調整してアップロードします。
- Q&Aは回答内の文字を選択し、「リンクを挿入」で表示する文字とリンク先を指定できます。直接 `[表示する文字](https://example.com/)` や `**太字**` を入力することもできます。Q04の既存FTリンクは自動復元します。
- TEAMはメンバーを選び、「制作実績」に1行1件ずつ入力します。作品名の追加・変更・削除と、行の順序変更で担当作品を編集できます。「シェイプキー制作」の見出しも変更できます。公式サイトでは1〜5件目が最初の列、6〜10件目が右の列、11〜15件目がその次の列に並びます。列が増えた場合はカード内だけ横にスクロールできます。
- 保存→プレビュー→更新して公開、の順に確認してください。プレビューでは全ての商品ページを縦に並べて表示します。

## ローカルで確認

Node.js 22以上。追加パッケージは不要です。

```powershell
node scripts/build.mjs
node scripts/dev.mjs
```

http://localhost:8788/admin/ を開き、`addhard-local` でログインします。この初期パスワードはローカル専用です。サーバーはこのPCからのみ接続できます。下書きはGit管理対象外の `.local/draft.json` に保存します。終了は実行画面で Ctrl+C。

検証：`node --test`。`node scripts/import.mjs` は初回移行専用です。編集開始後に実行すると公開データを元のHTMLから上書きするため、通常は実行しません。

## Cloudflare Pagesへ導入

1. このコードを `ADDHARD/addhard-official` の公開ブランチへ反映します。
2. Pagesのプロジェクト設定を、リポジトリルートを作業ディレクトリ、ビルドコマンド `node scripts/build.mjs`、出力ディレクトリ `dist` にします。既存の `ADDHARD` サブディレクトリ設定がある場合は変更が必要です。Functionsはルートの `functions/` から読み込まれます。
3. Cloudflare D1データベースを作成し、`schema.sql` を実行してテーブルを用意します。PagesのBindingsに `DB` という名前で接続します。本番とプレビューは別DBにしてください。
4. Pages Functionsの暗号化されたシークレットに以下を登録し、再デプロイします。GitHubトークンはチャット・HTML・リポジトリに書かないでください。

|設定|内容|
|---|---|
|`ADMIN_PASSWORD`|十分に長い管理者パスワード（ローカル初期値を使用しない）|
|`SESSION_SECRET`|32文字以上のランダム値。変更すると全ログインが失効|
|`GITHUB_TOKEN`|対象リポジトリ限定のfine-grained token、Contents read/write権限|
|`GITHUB_BRANCH`|公開ブランチ。通常は `main`|

5. Git連携で `main` への変更が本番ビルドを開始することを確認します。プレビュー環境には本番GitHubトークンを登録しないでください。プレビューには別DB・管理者設定を使用します。
6. `https://addhard-official.pages.dev/admin/` でログインし、下書き保存→プレビュー→更新の順で確認します。GitHubへの送信後、Cloudflareのデプロイ成功と公式サイトの表示を確認してください。

保存処理と秘密情報の実装は [CloudflareのBindings](https://developers.cloudflare.com/pages/functions/bindings/)、公開処理は [GitHub Contents API](https://docs.github.com/en/rest/repos/contents) に基づいています。

## データと公開の仕組み

- 公開の編集データは `data/content.json`。並び順は配列の順番です。トップはNEWS先頭4件、一覧は全件。Q&Aは全件です。商品コレクションは `shapekeys`、`eyeTextures`、`tools` です。旧形式に商品配列がない場合だけ `lib/catalog-defaults.js` の初期商品を補完し、既存の下書き・公開SHAを保持します。空配列は意図した全削除として維持します。
- TEAMコレクションは `team` です。配列がない旧データは `lib/team-defaults.js` の既存3名を補完します。担当作品は各メンバーの `credits` に保存します。旧編集画面がTEAMを省略して保存しても、保存済みのTEAMを消さないように保持します。
- ビルド時に従来のHTML/CSS/画像を引き継ぎ、ルートトップ、HTMLトップ、複数のNEWS一覧へ同じデータを反映します。旧JavaScriptによる一覧の上書きは生成物で停止します。
- プレビューは管理画面内の専用フレームへ表示します。公式サイトで使うフォント・HTTPS画像・動画の配信元を許可し、スクリプトは実行しません。商品カルーセルの全ページを縦に並べ、後ろの商品も確認できます。カルーセル操作は公開サイトで確認してください。
- 本番下書きはD1。ログインは8時間の署名付きHttpOnly Cookie。変更系APIは同一Originのみ受け付けます。ログインはIPごとに15分10回までです。
- 下書きの世代番号で同時編集を検知。公開はGitHubのファイルSHAで競合を検知します。外部から公開JSONが変更された場合は自動上書きせず停止します。その場合はDBの下書きとGitHubを管理者が比較・統合して、base_shaも最新SHAへ更新してください。
- GitHubへの書き込みは公開JSONの1ファイルだけです。下書きやログイン情報はコミットしません。公開直前に保存され、確認画面を経て送信されます。
- 回答内のリンクと太字を安全に表示します。自由なHTMLは解釈せず文字として扱います。サイトの外枠とカードのデザインは維持します。
- アップロード画像は既存のD1へ保存し、必要な `media` テーブルを自動作成します。追加のCloudflare設定は不要です。アップロードはログインと同一Originを必須とし、ファイル内容・形式・800KBの上限を検査します。公開前は認証済み管理者だけが画像を取得できます。GitHubへの送信成功後、その内容から参照される画像だけを公開配信に切り替えます。未使用の下書き画像は公開しません。画像の公開フラグ更新に一時的な失敗があっても、配信中の公開JSONから参照される画像は取得できます。
- 画像はD1に保存されるため、データベースのバックアップも必要です。公開済み画像は過去の公開版へ戻すため保持します。現在は未使用画像の自動削除は行いません。
- 現段階では公開完了の自動監視、変更履歴画面、パスワード再発行、メンバープロフィールの編集・新規登録、予約公開は未実装です。GitHubコミット履歴から公開JSONを戻して再ビルドできます。

## 今後の拡張

メンバープロフィールの編集や、大量の画像を扱うための専用ストレージに拡張できます。予約公開は別WorkerのCronと公開ジョブテーブルを追加し、入力日時をAsia/Tokyoで解釈してUTCで保存する予定です。実行中ロックと公開SHAによる重複防止を共通の公開処理へ組み込んでください。
